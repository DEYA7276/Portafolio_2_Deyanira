Estrategia de Caché Dinámica con Fallback a IndexedDB / Network-First

Consumo de una API REST remota mediante fetch con estrategia Network-First: la aplicación intenta obtener la versión más reciente desde la red; al recibir el JSON, guarda automáticamente una copia local sincronizada en IndexedDB y Cache API. Si el dispositivo pierde la conexión, la interfaz detecta la desconexión y renderiza inmediatamente el último snapshot almacenado.

Flujo de la Estrategia Network-First

Comportamiento secuencial del ciclo de petición y almacenamiento

1
Intento de Red Primario: Se emite una llamada fetch() al endpoint REST de producción.
2
Respaldo Reactivo: Al recibir la respuesta HTTP 200, el JSON se deserializa y se almacena en el IDBObjectStore ('api_posts') con timestamp.
3
Fallback Transparente: Si falla la red (timeout, offline o error 5xx), la promesa cae en catch() y lee automáticamente el snapshot de IndexedDB sin romper la UI.
